# 1. Por que gerenciar um projeto Front-End?

Projetos Front-End tendem a crescer rapidamente. A ausência de planejamento e gestão gera problemas recorrentes:
* Tarefas esquecidas e requisitos confusos;
* Retrabalho e conflitos no Git;
* Atrasos nas entregas e problemas de integração;
* Dificuldade para acompanhar o progresso real da equipe.

Em contrapartida, com processos de gestão estruturados, o projeto ganha:
* **Responsabilidades claras** para cada membro;
* **Prioridades bem definidas**;
* **Entregas incrementais** e contínuas;
* **Acompanhamento transparente** do progresso;
* **Redução drástica do retrabalho**.

---

# 2. Gestão de Projetos Front-End

Gerenciar projetos Front-End consiste em organizar pessoas, tarefas, tecnologias e prazos para transformar uma ideia inicial em uma aplicação web funcional. O processo exige planejamento contínuo, acompanhamento e ajustes para garantir o alinhamento com os objetivos do produto.

---

# 3. Gestão de Requisitos, Histórias e Tarefas

O fluxo começa com uma ideia, que é convertida em requisitos claros e organizada em um backlog. A divisão padrão ocorre em três níveis:

1. **Requisito (Macro):** O que o sistema deve fazer em alto nível.  
   * *Exemplo:* "O sistema deve permitir gerenciamento de tarefas."
2. **User Story (História de Usuário):** A perspectiva do valor entregue ao usuário final.  
   * *Exemplo:* "Como usuário, quero criar uma tarefa para organizar meu dia."
3. **Tarefas (Tasks):** As atividades técnicas e práticas para concretizar a história.  
   * *Exemplos:* Criar formulário, criar componente, validar campos, integrar API, criar testes.

---

# 4. Gestão do Backlog, Prioridade e Estimativa

* **Backlog:** Repositório central que reúne funcionalidades, melhorias, correções e débitos técnicos necessários para desenvolver e evoluir o produto.
* **Priorização:** Ajuda a equipe a determinar o que deve ser desenvolvido primeiro, considerando restrições, objetivos de negócio e necessidades do usuário.
* **Estimativas:** Auxiliam a equipe a compreender a complexidade relativa das atividades antes de assumi-las para um ciclo de trabalho.

---

# 5. Definition of Done (Critérios de Conclusão)

A **Definition of Done (DoD)** estabelece o conjunto rigoroso de critérios necessários para considerar uma tarefa ou história **realmente concluída**.

* **Exemplos de critérios comuns:** Código implementado, testes realizados, revisão de código (*code review*) aprovada, responsividade verificada em diferentes telas e integração realizada com sucesso.

---

# 6. O Framework Scrum

O **Scrum** é um framework ágil voltado para o desenvolvimento de produtos complexos de forma incremental. Ele promove inspeção frequente, adaptação contínua e entregas rápidas de valor.

* **No Front-End:** O Scrum auxilia a organizar os requisitos, priorizar funcionalidades visuais, planejar Sprints de trabalho e monitorar o andamento das entregas da equipe através de ferramentas visuais (como o Kanban).
